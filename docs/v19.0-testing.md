# Faveo Helpdesk 19.0 testing

## Scope and dependency decision

Debian 13 Trixie does not package Faveo Helpdesk. The appliance installs the
official supported Community release v2.0.3 and verifies archive SHA-256
`8b42f15c164a2e7cdf87ab53ed00c3c806ac7efa96e201405886fe559af93252`.
PHP 8.4, MariaDB, Apache, Redis, Supervisor and available PHP extensions come
from signed Debian Trixie repositories.

Upstream's current Community page directs users to the maintained
`faveosuite/faveo-helpdesk` repository. Its security policy lists v2.0.3 as
the supported patch line. Upstream is actively developing its PHP 8.4 and
Laravel 12 successor branch, but no newer stable Community release is
published, so the appliance does not ship that development branch.

## Static and economical preflight checks

```sh
bash -n conf.d/downloads conf.d/main tests/v19.sh \
  overlay/usr/lib/inithooks/firstboot.d/20regen-faveo-helpdesk-secrets \
  overlay/usr/lib/inithooks/firstboot.d/40faveo-helpdesk
python3 -m py_compile overlay/usr/lib/inithooks/bin/faveo-helpdesk.py
git diff --check
```

A disposable Debian Trixie container installed Faveo v2.0.3 on PHP 8.4,
completed the real interactive installer and all migrations, served the
application through Apache, authenticated the configured administrator and
created a ticket through the web form. Direct MariaDB queries verified the
ticket subject and body. Redis answered and a Faveo queue worker completed.

## Known limitation and deferred issues

- Docker runtime validation does not exercise the installer, appliance
  kernel, bootloader or physical hardware. Faveo adds no appliance-specific
  behavior at those boundaries, so the validated Core 19 baseline supplies
  inherited evidence.
- Faveo documents PHP IMAP as optional and only required when departments
  download inbound email directly. Debian Trixie does not provide
  `php-imap`, so web ticketing, outbound mail and the default application flow
  are covered while optional inbound IMAP retrieval is unavailable.
- PHP 8.4 emits deprecation notices from Faveo's vendored Laravel 9 and
  Monolog code on CLI startup. They do not affect the tested web, database,
  queue or scheduler flows. Upstream's active Laravel 12 branch removes this
  compatibility debt, but it is not yet a stable Community release.
